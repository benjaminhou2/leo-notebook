# Leo 本地学习门户系统设计

## 1. 设计目标

本地学习门户的核心不是“展示资料列表”，而是让 Leo 和家长能看清三层关系：

```text
原始素材 -> 系统分析 -> 需要加强的知识点 -> 对应提升习题
```

首版只服务本地家庭使用，不引入数据库，不做复杂账号系统。

## 2. 首页信息架构

登录后首页分成两部分：

1. 各科原始素材与系统分析
   - 按科目展示。
   - 每份资料展示原始素材链接。
   - 每份资料展示系统分析摘要。
   - 分析由项目学习技能生成或维护：语文阅读用 `$chinese-reading-diagnosis`，语文作文用 `$chinese-composition-coach`，数学用 `$math-homework-diagnosis`，跨学科汇总用 `$student-homework-diagnosis`。

2. 分科知识点提升清单
   - 按科目展示。
   - 每个知识点说明为什么要补。
   - 每个知识点连接到对应原始素材。
   - 每个知识点连接到单独的提升习题文件。

## 3. 目录模型

每个科目使用三层目录：

```text
科目/
├── 原始素材/
├── 教学分析/
└── 提升习题/
```

职责：

- `原始素材/`：保存照片、试卷图片、作文索引或其他来源资料。
- `教学分析/`：保存诊断方案、错题讲解、Leo 学习页、训练说明。
- `提升习题/`：按知识点拆分练习文件，一份知识点至少一个习题文件。

作文等历史专题目录可以继续保留，但接入门户时应通过 `config/content-index.json` 建立关系。

## 4. 配置模型

`config/content-index.json` 使用门户模型：

- `subjects`：科目和三层目录位置。
- `materialGroups`：原始素材与系统分析的组合。
- `knowledgePlans`：需要加强的知识点和对应习题。

关键关系：

```text
materialGroups.rawFiles -> 原始素材文件
materialGroups.analysis.file -> 教学分析文件
materialGroups.learningLinks -> Leo 学习页或训练单
knowledgePlans.evidenceMaterialIds -> 关联 materialGroups
knowledgePlans.practiceFiles -> 提升习题文件
```

## 5. 网站运行模型

根目录 `config/` 是唯一人工维护配置源。

网站启动前通过 `网站/scripts/sync-config.mjs` 同步：

```text
config/ -> 网站/public/config/
学科资料 -> 网站/public/materials/
```

浏览器只读取 `网站/public/` 下运行副本。运行副本不手工编辑。

## 6. 后续扩展方向

- 增加内容索引校验脚本。
- 让诊断技能自动补充 `materialGroups` 和 `knowledgePlans`。
- 给每个知识点增加完成状态。
- 增加家长总览页。
- 公网访问前重新设计认证方式。
