## 2. 项目背景

Leo 当前处于中国小学五年级下学期。日常学习会持续产生大量分散素材，包括：

- 语文、数学、英文测试试卷。
- 语文作文原稿、转写稿和老师批改稿。
- 各科日常作业、练习册、错题和订正。
- 老师评语、得分、扣分标记和阶段反馈。
- 系统生成的诊断、讲解、专项训练和复习记录。

这些素材如果只按文件保存，很难持续回答以下问题：

- Leo 当前真正薄弱的知识点是什么？
- 某个问题是偶发失误，还是已经多次重复出现？
- 问题属于知识不会、方法不稳、表达不完整，还是检查习惯不足？
- 最近应该优先复习什么，练习多少，怎样判断已经掌握？
- 第一轮练习后还有哪些问题，第二轮应该如何针对性加强？
- 随着年级、教材和学段变化，历史学习记录怎样继续发挥作用？

因此，本项目需要从“学习资料门户”逐步升级为“以证据为基础的个人学习诊断与提升系统”。

## 3. 项目愿景

建立一套长期服务 Leo 的个性化学习系统，从当前小学五年级下学期开始，持续支持后续六年级、初中和高中阶段的学习。

系统不只保存资料，而要形成以下完整闭环：

```text
学习素材录入
  -> 原始证据识别与结构化
  -> 学科专项分析
  -> 薄弱知识点定位
  -> 家长确认
  -> 第一轮诊断训练
  -> 错因分析
  -> 第二轮针对性强化
  -> 掌握度更新
  -> 间隔复习
  -> 阶段学习画像与计划
```

最终目标是：

- 更准确地发现 Leo 的个性化薄弱点。
- 减少无目标、重复和低质量刷题。
- 让每次练习都能追溯到真实学习证据。
- 让家长快速知道“现在最应该帮助什么、怎么帮助”。
- 让 Leo 清楚知道“今天学什么、为什么学、怎样算过关”。
- 形成可跨年级延续的个人知识画像和学习历史。

## 4. 产品定位与边界

### 4.1 产品定位

本项目是家庭自用的个人学习诊断、复习和提升系统，不是面向学校或大量学生的通用教务平台。

系统重点服务一个学生的长期学习，因此应优先保证：

- 个性化深度，而不是学生数量。
- 证据可追溯，而不是只输出结论。
- 学习闭环，而不是只生成一次报告。
- 内容质量，而不是题目数量。
- 家长可维护，而不是依赖开发人员日常操作。

### 4.2 当前范围

当前主要支持：

- 语文：基础知识、阅读理解、作文。
- 数学：概念、计算、单位、几何、统计、数量关系、应用题。
- 英文：词汇、拼写、句型、语法、阅读、听力反馈和写作。
- 素材类型：图片、PDF、转写文本、Markdown、HTML 和结构化记录。
- 学段：当前以五年级下学期为主，数据结构需要支持后续学段升级。

### 4.3 暂不作为第二阶段重点

- 面向多家庭或多学校的商业化多租户系统。
- 排名、积分、随机奖励等重游戏化功能。
- 自动替代老师或家长作最终教育判断。
- 在没有证据的情况下自动给孩子贴能力标签。
- 大规模云端训练模型或重型本地模型部署。

## 5. 用户角色

### 5.1 家长

主要任务：

- 上传和整理学习素材。
- 查看系统分析与原始证据。
- 确认、修正或驳回系统识别结果。
- 查看薄弱知识点、优先级和学习趋势。
- 为 Leo 安排当天或本周训练。
- 维护模型、技能和提示词配置。

家长需要看到的是可解释、可操作的结论，而不是大段泛泛的模型分析。

### 5.2 Leo

主要任务：

- 查看今天需要学习的内容。
- 阅读简短、清楚的错题讲解。
- 完成第一轮诊断和第二轮强化。
- 查看每道错题的原因和改进方法。
- 完成自查并看到当前掌握进度。

Leo 页面需要轻量、聚焦、低干扰，不承担复杂配置和管理功能。

### 5.3 系统维护者

当前通常由家长兼任，主要任务：

- 管理学科技能、提示词和模型配置。
- 检查智能分析运行情况。
- 维护知识点体系和教材范围。
- 处理失败任务、低置信度识别和数据备份。

## 6. 核心业务原则

### 6.1 原始证据优先

- 原图、原卷、学生原答案、老师批注和人工修正内容不得被覆盖。
- 所有薄弱点都应能追溯到具体素材、页码、题号、原句或批注。
- 图片或手写内容不确定时必须标记 `需复核原卷`。

### 6.2 分析与事实分离

系统应明确区分：

- 原始内容。
- OCR 或视觉识别结果。
- Leo 的答案。
- 标准答案或参考答案。
- 老师批改结果。
- 系统分析判断。
- 家长确认结果。

### 6.3 一次聚焦少量关键问题

- 一次训练优先解决 1-3 个最影响得分的问题。
- 不以生成大量题目作为成功标准。
- 默认每次训练控制在 10-20 分钟。

### 6.4 结论必须可解释

系统不能只写“阅读能力弱”或“数学基础差”，应写成：

- 哪份素材中的哪道题暴露了问题。
- Leo 当时如何作答。
- 正确要求是什么。
- 问题属于哪个知识点或技能。
- 为什么把它判断为 P0、P1 或 P2。

### 6.5 人工确认优先于自动写入长期画像

模型分析可以自动生成草稿，但进入长期知识画像前，家长应能：

- 修改知识点。
- 修改错因。
- 调整优先级。
- 删除误判。
- 标记暂不处理。
- 确认写入个人画像。

## 8. 主要使用流程

### 8.1 新素材处理流程

1. 家长选择科目和素材类型。
2. 上传图片或 PDF，系统保留原始文件。
3. 系统完成清晰度检查、旋转、页序和重复文件检查。
4. 系统识别题目、答案、批改、分数和作文文本。
5. 系统根据科目和素材类型选择对应技能。
6. 系统输出结构化分析草稿，并逐条连接原始证据。
7. 家长确认或修正分析结果。
8. 系统将确认后的薄弱点写入 Leo 的知识画像。
9. 系统建议第一轮训练内容。

### 8.2 两轮训练流程

1. 第一轮围绕确认后的薄弱点进行基础诊断。
2. 系统记录每题答案、错误标签和错误类型。
3. 系统判断是概念不会、方法不稳、计算错误、表达不完整还是检查不足。
4. 第二轮根据第一轮错因生成新情境、新数字或新表达的针对性题目。
5. 第二轮不得简单重复第一轮题干或选项。
6. 完成后更新掌握度，并安排间隔复习。

### 8.3 日常学习流程

Leo 登录后优先看到：

- 今天需要完成的 1-3 个任务。
- 每个任务预计用时。
- 为什么要练。
- 完成和过关标准。
- 尚未完成的复习任务。

家长登录后优先看到：

- 待确认的素材分析。
- 当前 P0 薄弱点。
- 最近训练结果。
- 重复出现的问题。
- 本周建议陪练内容。

## 9. 第一阶段需求与实现状态

### 9.1 第一阶段目标

第一阶段目标是建立基础资料门户和最小学习闭环：

```text
素材录入 -> 系统分析 -> 薄弱知识点 -> 两轮测试 -> 成绩记录
```

| 模块 | 当前能力 | 状态 |

| 资料目录 | 采用原始素材、教学分析、提升习题三层目录 | 已实现 |

### 9.3 第一阶段已经形成的价值

- 学习资料开始从散乱文件转为按科目和用途管理。
- 原始素材、诊断分析和提升练习之间已经建立基础关联。
- 家长可以从网站录入新素材和新知识点。
- Leo 可以在同一系统内完成专项测试并立即看到结果。
- 系统已经具备向长期个性化学习平台演进所需的基础数据对象。

### 9.4 第一阶段当前局限

- 页面已经有概览和分科空间，但没有围绕“待处理、待确认、今日学习、复习计划”组织完整任务流。
- 素材分析主要依赖一段通用提示词，项目内已有技能没有进入网站实际调用链。
- 文本模型无法直接理解图片时，只能根据文件名推断，容易产生泛化结论。
- 模型失败后的占位分析容易看起来像真实分析，存在误导风险。
- 新建知识点时会自动生成通用模板题，题目可能只在考学习态度，没有真正考查知识。
- 第二轮智能生成只覆盖部分场景，不是语文、数学、英文统一能力。
- 当前出题缺少跨轮次去重、选项质量检查、难度控制和答案一致性检查。
- 知识点、素材和练习数据同时存在 JSON 文件与 MySQL 数据库中，唯一数据源边界需要重新明确。
- 英文目录已建立，但素材、诊断、技能和练习闭环尚未真正形成。

## 10. 第一阶段使用反馈与根因分析

### 10.1 功能布局不够清晰完整

现象：

- 当前主要按“概览、语文、数学、英文”组织。
- 素材、知识点和测试放在同一分科页面中，但待办任务、确认任务和学习计划不突出。
- 家长管理功能与 Leo 学习功能没有明显分层。

根因：

- 第一阶段以展示已有数据为主，尚未按完整业务流程设计信息架构。
- 缺少“工作台”和“任务状态”概念。
- 缺少长期画像、复习计划和智能配置等一级模块。

### 10.2 素材理解与分析能力偏弱

现象：

- 分析结果容易停留在标题、摘要、优势和待提升项。
- 不能稳定还原每道题、Leo 原答案、老师批改和具体扣分依据。
- 有时只能根据文件名和学科常见问题进行推断。
- 已有学科技能没有自动参与网站分析。

根因：

- 缺少“图像预处理 -> OCR/视觉识别 -> 题目切分 -> 学科技能分析 -> 证据校验”的多阶段流程。
- 提示词过于通用，没有按素材类型和学科细分。
- 缺少人工校对界面和分析置信度。
- 缺少标准化结构输出和质量检查。

### 10.3 两轮加强测试不够智能

现象：

- 第一轮和第二轮可能出现重复或高度相似的题目。
- 新建知识点时的默认题目与真实知识内容关联较弱。
- 选择题干扰项可能明显错误、长度失衡或缺少迷惑性。
- 第二轮没有稳定根据第一轮错因进行迁移训练。

根因：

- 缺少统一的题目生成规划器。
- 缺少历史题目库和语义去重机制。
- 缺少学科级出题规则和选项设计规则。
- 缺少自动质量检查和人工发布前预览。
- 部分题目仍通过固定模板和简单轮换生成。

### 10.4 技能和提示词缺少管理界面

现象：

- 关键模型提示词直接写在服务代码中。
- 无法在页面查看某项分析使用了哪个技能、提示词和模型。
- 修改提示词需要改代码，无法测试、比较或回滚。

根因：

- 技能、提示词和模型尚未作为正式业务对象管理。
- 缺少版本、启停、测试和运行记录。
- 缺少不同任务到不同技能和模型的路由配置。

## 11. 第二阶段总体目标

第二阶段的目标不是继续堆叠页面，而是把第一阶段的基础闭环升级为可信、可配置、可持续优化的个性化学习系统。

第二阶段重点解决四件事：

1. 重构功能布局，让家长和 Leo 都能快速找到当前任务。
2. 建立基于技能的深度素材分析流水线。
3. 建立高质量、可去重、能根据错因调整的两轮出题系统。
4. 建立技能、提示词和模型的可视化管理能力。

## 12. 第二阶段功能清单

### 12.1 P0：信息架构与工作台重构

#### 目标

让系统从“按科目展示资料”升级为“按任务完成学习闭环”。

#### 功能要求

- 增加家长工作台：
  - 待分析素材。
  - 待人工确认的分析。
  - 当前 P0 薄弱点。
  - 待生成或待审核的训练。
  - 本周学习趋势。
  - 需要复核原卷的内容。
- 增加 Leo 今日学习页：
  - 今日 1-3 个任务。
  - 预计总用时。
  - 任务原因。
  - 过关标准。
  - 继续上次未完成任务。
- 一级导航建议调整为：
  - 工作台。
  - 素材中心。
  - 知识画像。
  - 训练与复习。
  - 学习报告。
  - 智能配置。
- 学科作为筛选条件和内容维度，不再承担全部一级导航职责。
- 家长功能和 Leo 学习功能使用不同入口或清晰的模式切换。
- 所有任务增加状态：
  - 待处理。
  - 分析中。
  - 待确认。
  - 待生成训练。
  - 待学习。
  - 已完成。
  - 待复习。

#### 验收标准

- 家长登录后 2 次操作以内可以找到待确认素材和当前 P0 薄弱点。
- Leo 登录后第一屏能直接看到今天要完成的任务和预计用时。
- 任意一份素材都能看到其当前处理状态和下一步操作。
- 一级导航覆盖完整学习闭环，不需要依赖文件目录理解系统。

### 12.2 P0：素材录入与深度分析流水线

#### 目标

把一次模型调用升级为可复核、可追溯的多阶段素材理解流程。

#### 功能要求

- 上传前处理：
  - 图片方向检测和旋转。
  - 清晰度检查。
  - 重复文件检查。
  - 多页顺序调整。
  - PDF 分页处理。
- 素材分类：
  - 科目。
  - 年级和学期。
  - 教材版本。
  - 单元或章节。
  - 素材类型。
  - 是否包含答案或老师批改。
- 结构化识别：
  - 题目编号。
  - 题干。
  - 题型。
  - 分值。
  - Leo 答案。
  - 老师批改。
  - 正确答案或参考答案。
  - 页码和证据区域。
- 学科技能路由：
  - 语文阅读使用 `$chinese-reading-diagnosis`。
  - 语文作文使用 `$chinese-composition-coach`。
  - 数学使用 `$math-homework-diagnosis`。
  - 混合材料使用 `$student-homework-diagnosis`。
  - 新增独立的英文诊断技能。
- 深度诊断：
  - 区分知识点缺口、技能缺口、习惯问题和材料难度问题。
  - 输出具体错因，不只输出宽泛知识点。
  - 每个薄弱点关联题号、原答案和批改证据。
  - 识别重复出现的历史问题。
  - 给出 P0、P1、P2 优先级及理由。
- 人工确认：
  - 支持逐题修改识别文本。
  - 支持修改知识点和错因。
  - 支持确认、驳回和标记 `需复核原卷`。
  - 未确认的结果不得直接进入长期掌握度计算。
- 失败处理：
  - 模型失败时明确显示失败，不得用看似真实的占位结论冒充分析结果。
  - 支持重新运行、切换模型和保留失败日志。

#### 验收标准

- 每个确认后的薄弱点至少关联一条具体原始证据。
- 系统能区分“识别事实”和“模型判断”。
- 低置信度内容自动标记并进入人工复核清单。
- 代表性测试素材中，题目、答案和批改可以逐题查看和修正。
- 网站实际调用的技能、提示词版本和模型可以在运行记录中追溯。

### 12.3 P0：个人知识画像

#### 目标

把零散薄弱知识点升级为持续变化的个人知识掌握地图。

#### 功能要求

- 建立语文、数学、英文分学段知识点树。
- 知识点至少包含：
  - 学科。
  - 年级和学期。
  - 教材章节。
  - 上级知识点。
  - 前置知识点。
  - 掌握标准。
- 每个知识点显示：
  - 当前掌握度。
  - 结果置信度。
  - 最近一次证据。
  - 历史出现次数。
  - 最近训练成绩。
  - 当前优先级。
  - 下一次复习日期。
- 掌握度不能只看一次分数，应综合：
  - 原始测试表现。
  - 第一轮训练。
  - 第二轮训练。
  - 间隔复习。
  - 同类新素材中的迁移表现。
- 支持查看知识点的完整证据时间线。

#### 验收标准

- 任意薄弱知识点都可以追溯到素材和训练记录。
- 同一知识点多次出现时合并到同一知识画像，而不是重复创建卡片。
- 家长可以看出“新问题、持续问题、正在改善、已基本掌握”四种状态。
- 年级升级后保留历史记录，并允许更新当前教材范围。

### 12.4 P0：高质量两轮测试生成系统

#### 目标

让第一轮负责准确诊断，第二轮负责真正针对错因强化，而不是简单换题或重复题目。

#### 第一轮要求

- 题目必须来自已确认的薄弱点和原始证据。
- 先生成训练规划，再生成题目。
- 每道题标记：
  - 目标知识点。
  - 细分能力。
  - 难度。
  - 题型。
  - 来源或变式依据。
  - 预期错因。
- 题量根据年龄和预计用时动态确定，不强制统一为 30 题。
- 优先使用旧错题变式，再补充新情境题。

#### 第二轮要求

- 必须读取第一轮的具体错题、错误答案和错因。
- 至少 70% 的题目针对第一轮暴露的问题。
- 其余题目用于检查知识迁移和防止短时记忆。
- 使用新数字、新语境或新表达，不得照抄第一轮题目。
- 如果第一轮已全部掌握，第二轮改为迁移巩固，不制造虚假薄弱点。

#### 选择题选项规则

- 每道选择题只能有一个明确正确答案。
- 干扰项必须来自真实常见错因，例如：
  - 运算顺序错误。
  - 单位混淆。
  - 概念边界混淆。
  - 阅读证据定位偏差。
  - 语法形式混淆。
- 干扰项与正确答案应在长度、语气和表达层级上尽量一致。
- 禁止使用明显敷衍选项，例如“随便选”“完全不管”“以上都不对”，除非题型本身确实需要。
- 禁止多个选项表达同一意思。
- 禁止答案泄露，例如正确选项明显比其他选项更完整。

#### 自动质量检查

- 结构检查：字段、题型、选项数量和答案格式正确。
- 重复检查：题干、核心条件、选项组合和语义相似度检查。
- 答案检查：答案必须存在于选项中，解析与答案一致。
- 学段检查：不超出当前年级和教材范围。
- 难度检查：符合本轮目标和 Leo 当前掌握度。
- 内容检查：题目必须真正考查目标知识点。
- 语言检查：表述清楚，没有歧义和不适龄内容。
- 不合格题目自动重新生成，不直接发布。

#### 人工审核

- 训练发布前提供题目预览。
- 支持逐题修改、删除、替换和重新生成。
- 支持锁定优质题，重新生成其他题。
- 保存题目版本和生成来源。

#### 验收标准

- 同一训练内无完全重复题。
- 第一轮与第二轮无完全相同题干，语义高度相似题占比不超过 10%。
- 每道选择题只有一个正确答案，且至少两个干扰项能对应合理常见错因。
- 第二轮至少 70% 题目可以说明其对应的第一轮错题或错因。
- 所有题目包含答案、解析、知识点、难度和生成来源。
- 家长可以在发布前预览和修改题目。

### 12.5 P0：技能管理中心

#### 目标

让学科诊断规则可以被网站实际调用、查看、维护和升级。

#### 功能要求

- 展示所有项目技能：
  - 技能名称。
  - 适用科目。
  - 适用素材类型。
  - 当前版本。
  - 启用状态。
  - 最近修改时间。
- 支持查看和编辑技能正文。
- 支持配置技能输入和结构化输出。
- 支持技能版本管理：
  - 新建版本。
  - 发布版本。
  - 回滚版本。
  - 比较版本差异。
- 支持任务路由：
  - 哪类素材使用哪个技能。
  - 主技能和辅助技能。
  - 失败时的备用技能。
- 增加独立英文技能，至少覆盖：
  - 词汇和拼写。
  - 句型和语法。
  - 阅读理解。
  - 英文写作。

#### 验收标准

- 网站执行素材分析时，能够读取启用中的项目技能，而不是使用代码内固定说明替代。
- 每次智能运行都记录技能名称和版本。
- 修改技能后不需要修改业务代码即可生效。
- 可以回滚到上一个稳定技能版本。

### 12.6 P0：提示词与模型管理中心

#### 目标

把大模型交互从代码中抽离，形成可配置、可测试、可追踪的智能能力管理层。

#### 提示词管理

- 按任务管理提示词模板：
  - OCR 后结构化。
  - 语文阅读分析。
  - 作文分析。
  - 数学分析。
  - 英文分析。
  - 第一轮出题。
  - 第二轮出题。
  - 题目质量检查。
  - 错因归纳。
  - 家长报告。
  - Leo 讲解。
- 支持模板变量，例如：
  - 学生信息。
  - 年级学期。
  - 教材版本。
  - 原始题目。
  - Leo 答案。
  - 历史薄弱点。
  - 第一轮错题。
- 支持草稿、启用、停用和版本回滚。
- 支持在测试区选择样例素材运行，比较不同提示词结果。
- 支持保存人工评分和备注。

#### 模型管理

- 配置模型服务商、模型名称和用途。
- 为不同任务分配不同模型，例如视觉识别、深度分析和低成本格式检查。
- 配置温度、输出格式、超时、重试和备用模型。
- 密钥只从安全环境配置读取，不在页面明文展示或写入代码。
- 显示模型可用状态和最近失败原因。

#### 运行记录

- 保存任务类型、输入摘要、技能版本、提示词版本、模型、耗时和结果状态。
- 支持查看失败原因并重新运行。
- 支持比较两次运行结果。
- 对涉及学生隐私的原始图片和文本设置明确保留范围。

#### 验收标准

- 业务提示词不再硬编码在服务接口中。
- 管理界面可以完成提示词新增、编辑、测试、启用和回滚。
- 每次智能分析都能追溯到具体模型、技能和提示词版本。
- API 密钥不出现在前端代码、版本库和普通运行日志中。

### 12.7 P1：训练计划与间隔复习

- 根据知识点掌握度自动建议复习日期。
- 支持当天、3 天后、7 天后和阶段性复查。
- Leo 今日任务优先安排：
  - P0 新问题。
  - 到期复习。
  - 第一轮未过关项目。
  - 第二轮后仍不稳定项目。
- 支持家长调整任务数量和每日总时长。
- 连续多次掌握后降低频率，不重复刷已经稳定的内容。

### 12.8 P1：学习报告

- 生成周报和月报。
- 展示：
  - 各科学习素材数量。
  - 新增薄弱点。
  - 重复薄弱点。
  - 已改善知识点。
  - 两轮训练效果。
  - 本周建议。
- 报告必须连接到具体证据，避免只给笼统评价。
- 支持生成家长版和 Leo 简版。

### 12.9 P1：数据治理与维护

- 明确数据库为动态业务数据的唯一来源，文件系统保留原始资料和正式输出文档。
- JSON 配置只保留静态站点和初始化用途，避免与数据库长期双向冲突。
- 增加内容索引、文件路径和数据库关联校验。
- 支持备份、恢复和导出。
- 支持删除或归档错误素材、错误分析和无效题目。
- 记录人工修改历史。

### 12.10 P2：跨学段与扩展能力

- 年级、学期和教材版本切换。
- 小学升初中、初中升高中时保留历史知识画像。
- 支持前置知识点和跨年级知识依赖。
- 根据新学段调整分析标准、题型和讲解语言。
- 在确有家庭远程访问需求时，再升级公网认证与隐私保护。

## 15. 非功能需求

### 15.1 性能

- 优先适配 8 GB 内存的 macOS 设备。
- 大模型任务采用后台状态，不阻塞页面其他操作。
- 图片上传后按需压缩分析副本，但保留原始文件。
- 避免在本机运行重型模型或大规模向量服务，除非后续确有必要。

### 15.2 可靠性

- 智能任务失败后可以重试，不重复写入数据。
- 保存素材、分析、知识点和训练时使用明确事务边界。
- 自动生成内容必须经过结构校验。
- 重要配置和数据支持备份恢复。

### 15.3 安全与隐私

- 学生原始资料默认只在本地或明确授权的模型服务中处理。
- API 密钥不得硬编码或进入版本库。
- 公网开放前必须升级认证方式。
- 运行日志不得记录完整密钥和不必要的学生隐私内容。

### 15.4 可维护性

- 技能、提示词、模型和知识点体系采用独立配置与版本管理。
- 业务代码不直接包含大段学科提示词。
- 每次智能运行可追溯、可复现、可比较。
- 新增学科或新素材类型时不需要重写主流程。

### 15.5 可用性

- 家长页面强调状态、证据和下一步操作。
- Leo 页面强调今天学什么、怎样做和怎样过关。
- 所有面向 Leo 的页面保持浅色、低饱和、清楚、无干扰。
- 不使用游戏化奖励替代真实学习反馈。

## 18. 第二阶段完成定义与实现状态

第二阶段只有同时满足以下条件，才能认为核心目标完成：

- [x] 家长能够从一个清晰工作台完成素材录入、确认、训练发布和结果查看。
- [x] 素材分析逐题连接原始证据，并实际使用对应学科技能。
- [x] 未确认或低置信度分析不会直接污染长期知识画像。
- [x] 第一轮和第二轮题目经过自动质量检查和人工预览。
- [x] 第二轮能读取第一轮错题、答案和错因标签，作为针对性生成输入。
- [x] 技能、提示词和模型可以在管理界面维护、启用、发布和回滚。
- [x] 任意智能结果都能追溯到所用技能、提示词和模型版本。
- [x] Leo 能在第一屏看到已发布的当天任务，并完成“学习、反馈、复习”的连续流程。
- [x] 家长能看到知识点从发现、训练到改善的完整证据链。

### 18.1 2026-06-07 实现结果

第二阶段已落地以下系统能力：

- 家长工作台、素材中心、知识画像、训练与复习、学习报告、智能配置六个一级模块。
- 家长端和 Leo 端双模式，以及桌面端、手机端响应式导航。
- 图片与 PDF 上传、文件保留、PDF 分页、图片清晰度检测、重复来源哈希和页面旋转。
- “素材结构化识别 -> 学科技能分析 -> 家长复核 -> 写入知识画像”两阶段分析链路。
- 语文阅读、语文作文、数学、英文和通用作业诊断技能路由。
- 知识点掌握度、证据置信度、状态、优先级、复习日期和证据时间线。
- 第一轮、第二轮训练生成，锁题重生成，题目编辑、删除、质量检查和发布。
- 题干近似重复、跨轮重复、敷衍选项、选项数量、答案、讲解和出题依据检查。
- Leo 端今日学习、错题讲解、到期复习、进步展示和自动批改。
- 技能、提示词、模型、任务路由和模型运行记录管理。
- 周报、月报、家长智能摘要、完整 JSON 备份和文件一致性检查。
- 一阶段历史素材分页迁移，以及 375 道历史题归入 12 个待复核训练计划。

### 18.2 当前需要家长确认或补充的业务信息

- Leo 当前各科教材出版社和具体版本仍标记为 `待确认`，知识目录已支持后续配置。
- 学校当前教学进度、单元范围和老师特殊要求尚未录入学生档案。
- 一阶段历史题不会自动发布。现有质量检查已经识别出敷衍选项和重复风险，应重新生成或人工修订后再发布。
- 数学期末综合自测有一条历史原图路径缺少实际文件，系统已在“智能配置 -> 数据维护”中明确报告，不会自动删除记录。
- 公网远程访问、正式服务端身份认证和多设备同步仍属于后续阶段。

## 19. 后续需求变更规则

- 新需求应先判断属于项目目标、业务规则、技术方案还是具体开发任务。
- 影响产品范围、核心流程、角色或验收标准的内容，应更新本文档。
- 影响学习分析细节的内容，应同步更新 `docs/项目业务规则.md` 和对应技能。
- 影响实现架构的内容，应同步更新 `docs/技术方案手册.md`。
- 具体版本排期和开发状态可以记录在 `docs/未来开发计划.md`，但不得与本文档的需求基线冲突。
